# Data licences and provenance

Every data source MedTrace uses, where it came from, what its licence permits, and how
to regenerate it. Required by `CLAUDE.md` rule 7: *open or synthetic only; document
every source — origin, licence, subset, how to regenerate.*

**No real patient data of any kind.** No MIMIC, no My Health Record, no eRx, no
pharmacy records, no Medicare numbers, no real IHIs. Every patient, every medication
statement and every discrepancy in this project is generated by
`scripts/generate_synthetic.py` from a seed. See `docs/DATA_SPEC.md`.

---

## 1. PBS public API v3 — real, used, **conditions worth reading**

| | |
|---|---|
| Source | `https://data-api.health.gov.au/pbs/api/v3` |
| Publisher | Department of Health, Commonwealth of Australia |
| Accessed | **2026-10-24**, schedule_code **4751** (October 2026) |
| Tables | `schedules`, `items`, `item-atc-relationships` |
| Access | Free, **no login**. A `subscription-key` header is required; the published unregistered key is used, read from `PBS_SUBSCRIPTION_KEY` in the gitignored `.env`. |
| Rate limit | One request per 20 s, **shared across every user of the public key**. `scripts/fetch_reference.py` pulls whole tables with 5000-row pages and **never makes a per-item call.** |
| Fetched by | `scripts/fetch_reference.py` |
| Stored at | `data/reference/raw/` — **gitignored** |

### The licence conflict, and how we resolved it

PLAN section 3 required reading the `_meta` copyright block before committing any
PBS-derived row. We did. **It is more restrictive than the CC BY 3.0 AU that is
reported elsewhere**, and this is its exact text:

> Copyright (c) 2024 Department of Health, Commonwealth of Australia
>
> Permission is granted to use and redistribute this content, as long as all copyright
> statements are retained. **Permission is not granted to modify this content.**
>
> For further copyright information of this content, please refer to:
> https://www.health.gov.au/using-our-websites/copyright

CC BY permits modification; this statement explicitly does not. Where a general licence
label and a statement attached to the data itself disagree, **we honour the statement
attached to the data**, because it is the one the publisher shipped with the bytes.

What that means in practice:

- **No PBS field value is ever altered.** `build_lexicon.py` *selects* rows and *copies*
  values (`pbs_code`, `pack_size`, `number_of_repeats`, `atc_code`) verbatim. It
  reshapes nothing and recomputes nothing from them.
- **The raw snapshot is not committed.** `data/reference/raw/` is gitignored, exactly as
  PLAN section 3 directed while the licence was unconfirmed. Resolving the licence did
  not loosen that; it confirmed it.
- **Only a ≤200-row attributed sample is committed**, at
  `tests/fixtures/reference/lexicon_sample.csv`, so tests and a judge's fresh clone work
  without a fetch.
- The copyright block itself is written to `data/reference/raw/pbs_copyright.txt` on
  every fetch, so it travels with the data it governs.

### What is *not* available, and was checked

PLAN section 3's backbone — the monthly "PBS API CSV files" ZIP — is **not** publicly
obtainable. Recorded in full in `docs/DECISIONS.md` (24 Oct); in short:

| Route | Result |
|---|---|
| Monthly CSV bundle | Published in the **embargo area**; needs an HPP/myID login |
| Legacy XML and text files | **Discontinued 1 May 2026** |
| `data.gov.au` PBS ATC Report | CC BY, but ATC **level-1 names only** — no codes, no item codes |
| PBS Date of Supply supplementary CSV | Not published on `data.gov.au`; the API route is the schedule, not supply volumes |

## 2. `data.gov.au` PBS Item Report — real, used for `dos_weight`

| | |
|---|---|
| Source | `data.gov.au`, dataset `14b536d4-eb6a-485d-bf87-2e6e77ddbac1` |
| Licence | **CC BY 3.0 Australia** (`cc-by`), as published on the dataset page |
| Attribution | Pharmaceutical Benefits Scheme (PBS) — Item Report, Department of Health, Commonwealth of Australia, used under CC BY 3.0 AU |
| Accessed | 2026-10-24 (resource: CSV PBS Item Report 2016 YTD, 27 MB) |
| Columns used | `Item_number`, `Services` |
| Used for | `dos_weight` in the lexicon — real prescription volumes, joined to `pbs_code` on `Item_number` |
| Stored at | `data/reference/raw/pbs_item_report_2016.csv` — **gitignored** |

**Two honest caveats.** This is **2016** utilisation data against the **October 2026**
schedule, so medicines listed since 2016 have no volume and get `dos_weight` `0.000000`.
And `dos_weight` does **not** drive sampling: `DATA_SPEC` section 4.2's within-bundle
shares do, and they live in `data/reference_src/medicines.csv`, generator-side. The
`dos_weight` column is reference information served to agents, nothing more.

## 3. Our own hand-built reference tables — committed

All three are **our own work**, written during the build window, licensed with the repo.

| File | Rows | Derived from | Notes |
|---|---|---|---|
| `data/reference_src/medicines.csv` | 104 products | `docs/DATA_SPEC.md` §4.2 (16 condition bundles) and §4.3 (combination traps), plus §6/§10.3 for the OTC and complementary items | Generics, Australian brands, strengths, regimens, within-bundle shares and **ATC codes are transcribed from the spec**, never invented. |
| `data/reference_src/apinchs_atc.csv` | **40**, verbatim | `docs/DATA_SPEC.md` §10.1 | The **concept** is ACSQHC's APINCHS, with extensions from SA Health (APINCHEN) and WA Health. The ATC-prefix *table* is our own construction. Two rows carry two prefixes each, so the built view has 42. |
| `data/reference_src/nicknames.csv` | 167 pairs | `docs/DATA_SPEC.md` §10.2 | Hand-selected for Australians born 1936–1966. **Not** copied from any dataset — see below. |

### ATC codes

**Every ATC code comes from `docs/DATA_SPEC.md`, not from general knowledge and not from
the PBS join.** The PBS `item-atc-relationships` table is read purely as a *cross-check*:
`build_lexicon.py` reports any disagreement between the spec and the API for a human to
resolve, and never applies one silently. The spec is the clinical contract; the API is
evidence about it.

### Nicknames

`docs/DATA_SPEC.md` §10.2 names `carltonnorthern/nicknames` (GitHub; PyPI `nicknames`;
**Apache-2.0**) as a public source. **We did not download or vendor it.** The spec's own
caveat is that it is US-genealogy-derived and biased, and it asks for ~100 pairs suited
to Australians born 1936–1966 — so the list is hand-written, including Australian
diminutives (Bazza, Gazza, Shazza) that no US dataset contains. The public source is
recorded here because the spec cites it, not because we used it.

## 4. Never committed, never used

| Thing | Why |
|---|---|
| AMT / SNOMED CT-AU bulk releases | Licensing. AMT-shaped codes in the lexicon are **clearly synthetic** (`SYN-AMT-MP-0001`) unless a real one came from the PBS `amt-items` table. |
| WHO ATC/DDD index | Licensing. Individual ATC codes for our ~100 medicines come from `DATA_SPEC`. |
| DDInter | Non-commercial share-alike; incompatible. |
| TGA ARTG bulk export | Not used. |
| Any real patient data | Rule 7, and the whole point of the project. |

### TGA Medicine Shortage Reports — parsed, **not wired up**

`scripts/load_tga_shortages.py` exists and is unit-tested, but nothing imports it,
nothing registers its output, and `queries.q_shortages` still raises. Q4 is **Monday and
optional**, sixth in PLAN section 4's cut order. If it is used, the licence and
attribution must be added here first. **The shortage database is incomplete, so it is
never ground truth** — anything derived from it renders as
`NoticeType.KNOWN_SHORTAGE` ("known shortage"), never as "unavailable".

## 5. How to regenerate

```bash
make data        # fetch_reference.py then build_lexicon.py
```

`data/reference/` is gitignored in full. Everything in it is reproducible from the
committed `data/reference_src/*.csv` plus a PBS fetch. Without a fetch,
`build_lexicon.py` still produces a complete, working lexicon — every code is simply
synthetic, which the build reports as a count rather than hiding.

**Declared in `docs/PREEXISTING.md`** as external, pre-existing data: the PBS schedule
(via the public API), the `data.gov.au` PBS Item Report, and the TGA shortage export.
