### [x] S5 · high · RUN_TIMEOUT_S late in a live run discards every finished result

**Where:** `app/orchestrator.py:181`

**What goes wrong:** In a live run that already takes the documented 6-8 minutes, the critique objects and triggers a revise round. Writer.draft and evaluator.critique each call ctx.check_time() first and raise RunTimeout once 600 s have passed. _llm_step catches only MeterlessError, so RunTimeout reaches _guard. _guard calls _respond(state, 'partial', ...) with no analysis and no findings. A slow Nemotron call during the demo leaves the judge with an empty result.
